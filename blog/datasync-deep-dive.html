DataSync: I built the wrong product first, on purpose

Sep 2026·6 min read
Next.js Supabase Postgres GitHub Actions SendGrid

I started DataSync as an alumni portal. It's a data-freshness SaaS now, and getting from one to the other is the actual story.

The problem that doesn't look like a problem

Every alumni network, every CRM, every HR directory has the same quiet failure mode: the data was correct once. Someone changed jobs, moved cities, got a new number, and nobody updated the record. Six months later 40% of it is stale, and nobody notices until they need it — a reunion mailer that bounces, a "recent grads" report that's wrong, an emergency contact that isn't.

The fix everyone reaches for is "send a reminder email asking people to update their info." It doesn't work. Nobody opens a cold email that says "please verify your details." It reads as spam even when it isn't.

So I built the alumni portal first, because it's a concrete version of the problem with a real audience I could reason about.

What's actually there

It's a Next.js 14 app on the App Router, Supabase for auth and Postgres, deployed on Vercel. Nothing exotic in the stack — the point was never the stack.

Auth is Supabase's own: sign up, confirm email, sign in, redirect. On sign-up, a server route creates a blank profiles row keyed to the user's id, so there's never a user without a profile to fill in. The profile page pulls that row, lets someone edit name, batch, and company, and calls a server route to save it. Every save stamps last_verified with the current timestamp. That column is the whole idea — it's not "did they ever fill this in," it's "how long ago did a human confirm this is still true."

There's a second button next to Save: Data is same. If nothing's changed, you don't have to re-type your own name to prove it — one click stamps last_verified without touching the fields. That button is the thing that makes the reminder emails work later, because it turns "update your profile" (effort, friction, a form) into "still true, yes/no" (one tap). People will do the second one.

The reminder job

A GitHub Actions workflow runs every Sunday at 09:00 UTC and calls send_reminders.js. It queries Supabase directly with the service role key — no API route in between, since it's a scheduled job, not a user action — for any profile where last_verified is null or older than six months, and where the last reminder itself was sent more than six months ago (so it doesn't nag someone every week forever). It emails through SendGrid, and every send updates last_reminder_sent so the same person doesn't get hit twice in one run.

I wrote it with a --dry flag from day one: run it locally, print who would get emailed, send nothing. I did not want to find out the query logic was wrong by mailing three hundred alumni at 9am on a Sunday.

Where it's actually going

The alumni portal is single-tenant — one organization, one Supabase project. The rewrite in progress is multi-tenant: an org signs up, gets an API key, drops a script tag on their own site, and the widget renders a data-portal for their users without them touching a database.

<script src="https://mysaas.com/sdk.js"></script>
<script>
  DataSync.init({ apiKey: 'your_api_key', containerId: 'data-portal' });
</script>
<div id="data-portal"></div>

That's the part that actually needs the alumni portal to have existed first. Row-level security policies, custom field configuration, white-label branding — none of that is guessable in the abstract. I know last_verified and last_reminder_sent matter because I watched them matter on a real dataset with a few hundred real people in it. The next version generalizes those two columns into whatever fields an org configures, keeps the "one-click confirm" pattern because that's the part that got replies, and turns the whole thing into something you embed instead of something you fork.

Alumni networks, healthcare intake, HR directories, association memberships — different shapes of the same failure. Build one instance properly, then find out what has to be configurable, not guessed.
